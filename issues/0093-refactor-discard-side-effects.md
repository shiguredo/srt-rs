# 破棄したパケットの受信副作用が残る

- Branch: feature/refactor-discard-side-effects
- Polished: {YYYY-MM-DD}

## 目的

`src/srt_receiver.rs` の `receive` メソッドが上限超過ギャップのパケットを破棄する際、破棄判定より前に実行された受信副作用が巻き戻されない。破棄したはずのパケットが統計・ACK 生成・レート推定・ラップ状態に影響を残し、攻撃者から誘発できる経路になる。破棄の純度を上げ、将来の不具合の温床をなくす。

## 現状

`receive` メソッド内の `total_received` と `packets_since_ack` の加算、レート推定器とリンク容量推定器の更新、ジッター計算、TSBPD ラップ開始フラグの設定が、ギャップ判定と破棄処理より前に実行される。破棄時は `packets` からの除去のみ行い、これらの副作用は残る。

影響はいずれも 1 パケット分に有界で、現状の実害は限定的であることがレビューで確認済みである。具体例として、`packets_since_ack` の加算により Light ACK や即時 NAK を誘発できること、ラップ開始フラグの残留により後続パケットの配信時刻計算にラップ補正が乗り配信が遅延しうることが挙げられる。

## 設計方針

破棄が確定した時点で副作用を巻き戻すか、ギャップ判定を挿入前に移動して破棄時は副作用を付けない。統計の定義 (受信したパケット数か受理したパケット数か) が曖昧なままなので、選んだ定義を `total_received` 等の `///` に明記する。

## 完了条件

- 上限超過で破棄したパケットが受信統計・ACK 生成・NAK 生成・配信時刻計算に影響しないこと
- 破棄前後で統計とカウンタが不変であることを検証するテストが `src/srt_receiver.rs` 内の `#[cfg(test)]` モジュールに追加されていること
- `CHANGES.md` の `## develop` セクションにエントリが追加されていること
- `cargo test --workspace` で全テストが通過すること
